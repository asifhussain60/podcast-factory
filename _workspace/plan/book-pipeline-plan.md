# Book PDF: one path, two knobs + visuals decoupled from content + human curation

## Context

Reading-edition PDFs from the podcast pipeline (*The Master and the Disciple*, *Mukhtasar al-Athar*) carry structural visual defects: Mermaid mindmaps overflow across page breaks (book1 pp.26-27), `NotebookLM`-watermarked raster slides used as diagrams (pp.8/25), duplicate captions (title echoed inside the figure AND in `<figcaption>`), figures marooned in whitespace or placed before the text that introduces them, and (book2) stiff word-for-word-from-Arabic prose.

Root cause: **presentation is fused into the content pipeline** (`_book_illustrate.py` auto-injects diagrams; `inject_slide_deck.py` auto-injects rasterized NotebookLM slides), the only sizing control is `book-print.css:349` (uncapped by design) + `_svg_geometry.py` (advisory, horizontal-only), and there is **no print/PDF-quality standard or challenger**. Separately, the pipeline has **two divergent book routes** (pure translation via `_translation_edition.py`; augmented companion via `_book_compose.py`) differing on three axes at once — upstream, augmentation, and voice.

User directions: (1) initial content must be **diagram-free**; visuals become a separate human-curated layer in the Podcast Factory Astro Site — review PDF + assets separately, delete/move/resize/place, then a "Generate PDF" button. (2) **Unify the two routes into one path** with independent knobs. Decision locked: augmentation and voice are **two independent knobs**. (3) Execute **autonomously across all phases**, committing after each. Accuracy is paramount — no change may alter a teaching.

## Cross-cutting contracts (apply to every phase)

Flag OFF reproduces today's output byte-for-byte; flag ON exercises the new path on the two fixture books. No `develop`->`main` (stays Tier 2). Merge feature->`develop` `--no-ff` only in the final phase.

## A. Unify the two routes into one path (two independent knobs)

Single book branch: **faithful translation is the base; augmentation is an additive gated layer on top.** Two orthogonal knobs in `series-config.yaml`, set at intake:

- `book_augmentation: none | source_only` — `none` stops at the faithful base; `source_only` runs new stage `0book-augment` adding enrichment grounded ONLY in reliable Islamic sources (`content/knowledge-base/` + `_doctrinal.py` packs) as clearly-labeled editorial blocks never blended into source (standard §4.3/§10), gated by BK-P4 + T1-T5.
- `book_voice: faithful | author_companion` — re-voice styling pass over the base; independent of augmentation.

BOTH modes compose the base faithfully from `_system/source/text/refined-english.md`. **Denoise/refine (incl. noise-auditor apparatus stripping) and the uploaded standard's recommendations sit BELOW the knobs and apply to both.** Retire standalone `generate_translation_edition.py`; fold into the orchestrator book branch. Zero-regression config map: `deliverable_mode: translation_edition` -> `{augmentation: none, voice: faithful}`; legacy companion -> `{augmentation: source_only, voice: author_companion}`.

## B. Decouple visuals; contract-first human curation

```
compose (text only) -> book/book.md               [zero figures]
collect visuals     -> book/visuals/*.svg|png      [candidates, NOT injected]
                       book/visuals/index.json     [id,type,aspect,caption,suggested-anchor,cleaned?]
-- HUMAN - Astro "Book Composer" -> writes book/visual-layout.json   [THE CONTRACT]
-- "Generate PDF" button -> render(book.md + visual-layout.json) -> book/book.pdf
```

Contract `book/visual-layout.json` (schema `book.visual-layout/v1`): placements `{visual_id, anchor, width_pct, align: left|center|right, flow: wrap|standalone, caption, page_fit: avoid|before|isolate-plate}`. Pipeline never injects — only offers. Renderer behavior: `flow: wrap` + `align: left|right` => CSS float with text flowing around the image beside the content (requires `width_pct <= 50` so text has a real column); `flow: standalone` => full-column centered block; `align: center` implies standalone. Explicit `width_pct` + one-figure-per-plate rule (a standalone figure taller than the text column can never split across pages). NotebookLM slides become library assets, auto-cleaned (crop watermark / prefer verified vector replica via `_slide_replicate.py`); human opts each in. API-first: Astro <-> small local endpoint (`GET/PUT visual-layout.json`, `POST render`).

## UI visual-QA loop (Phase 4 DoD; self-correcting, <=5 iterations)

Inventory every UI surface in scope (git diff + the app's primary screens) and how the repo runs locally; start the dev server (`preview_start` via `.claude/launch.json`) and confirm reachable. Then loop: for each surface capture screenshots at ~1440px desktop + ~390px mobile in each meaningful state (default, hover/focus, expanded/collapsed, empty, loading, error, theme variants) into a throwaway `./.visual-qa/` (record every path); open and judge each image against the repo's Cortex/`html-view-quality` standard, hunting concrete defects (clipping/overflow, truncation, overlap, misalignment, inconsistent spacing, low contrast, off-theme/hardcoded colors, broken/oversized SVGs, z-index glitches, broken responsive layout, missing focus styles); make the smallest correct in-pattern fix in source (tokens/existing components, no inline styles, no new deps, never regress a working area); re-screenshot only affected surfaces and re-judge. Repeat until a full pass surfaces zero actionable defects (cap 5; stop early on cosmetic churn). On convergence, delete only `./.visual-qa/` and the screenshots created, leaving the tree otherwise untouched, and report each issue -> fix -> file. Ground every judgment in a screenshot captured that iteration; never claim "looks good" from memory.
