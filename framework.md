## Podcast path vs PDF routes — two deliverables per book

Every book produces **two** deliverables on the same branch, in the same `content/<Bucket>/<slug>/` folder:

- **Podcast path — the podcast.** The final-reviewed, enriched per-chapter text in the **original author's voice** (`chapters/chNN-<slug>.txt`) is the SOLE NotebookLM source, one chapter → one episode. Gated by `podcast-challenger` (audio) + `slide-deck-challenger` (decks). [build_episode_txt.py](scripts/podcast/build_episode_txt.py) always selects the author-voice chapter — never `chapters/literary/` (wiring fixed 2026-06-04; regression-guarded by `scripts/podcast/tests/test_episode_source_wiring.py`).
- **Book path — the reading-edition PDF.** Phases `0book-design → 0book-compose → 0book-illustrate → 0book-slide-import → 0book-render` (gated by `series.enable_book_branch`, NON-blocking on the podcast ship, run post-finalize inside the publish driver so the book is built from review-approved content). `0book-compose` is ONE unified path ([scripts/podcast/_book_pipeline_v2.py](scripts/podcast/_book_pipeline_v2.py) `compose_book_v2`) selected by two orthogonal knobs in `_system/series-config.yaml`: `book_augmentation: none | source_only` and `book_voice: faithful | author_companion` ([scripts/podcast/_pipeline_flags.py](scripts/podcast/_pipeline_flags.py)). Compose runs a faithful base (the translation-edition composer, `author_translation_edition_compose`) → optional additive `0book-augment` ([scripts/podcast/_book_augment.py](scripts/podcast/_book_augment.py): source-grounded, clearly-labeled + doctrinally-gated editorial asides, non-destructive to the base) → optional `0book-voice` ([scripts/podcast/_book_voice.py](scripts/podcast/_book_voice.py): re-voice into the book's declared narrative frame, windowed at 4,500 words and reverted PER WINDOW on any teaching/Arabic/doctrinal/frame drift). A THIRD inline-Arabic operation, `5a-substitute` ([scripts/podcast/_book_substitution.py](scripts/podcast/_book_substitution.py) `apply_arabic_substitution`, REQ-BA-128, added 2026-08-03), then REPLACES a romanized glossary term with its script and collapses `amal (عَمَل)` to `عَمَل` — finishing the 2026-08-02 rule that the overlay only half-implemented, since CONVERSION needs a bracket the author wrote and ANNOTATION needs a term to append to, and neither reaches `the *mawaddah*`. It runs AFTER vowelling so the script it inserts is marked, decides eligibility by two POSITIVE conditions rather than a denylist (hardened 2026-08-03 after a post-merge sweep found it ready to print the English word `approach` as `الْمُبَاشَرَة`): the romanization must be a possible transliteration of its own script ([scripts/podcast/_translit_skeleton.py](scripts/podcast/_translit_skeleton.py), a structural consonant-skeleton match needing no corpus — which matters because the books it protects are the ones with no Arabic scan), AND the term's `annotation_class` must be `teach`, since structure cannot catch a wrong word spelled like the right one (`surah`/`صُورَة` is *picture*; `adam`/`آدَم` is *Adam the prophet* in a passage meaning `عَدَم`). On top of those it refuses absorbed English (Allah, imam, shaykh — REQ-BA-070's Merriam-Webster rule), names, titles, quotations, letters-as-letters (BK-N4), and any term that is only part of a longer romanized phrase (`*La ilaha illa Allah*` is left whole rather than shredded); and it is reversible by sidecar, because substitution deletes the romanization `_normalize_annotations` inverts by, so each run restores before re-deriving — with the fingerprint stamped from the FINISHED page by apparatus step 12 (four steps rewrite book.md after `5a-substitute`), an unverified record KEPT rather than dropped since `before_md` is the only copy of the English, and `revert_ineligible` taking back no-longer-eligible terms even when a wholesale restore is impossible. A deterministic, glossary-driven inline-Arabic pass ([scripts/podcast/_book_inline_arabic.py](scripts/podcast/_book_inline_arabic.py) `apply_inline_arabic`) then restores the Arabic SCRIPT beside inline terms, satisfying `R-ARABIC-SCRIPT-RETAINED` for INLINE terms — the composer reads `refined-english.md`, which carries no Arabic at all, so before this step only block quotations (transcribed from the OCR ground-truth pages) kept their script. Immediately BEFORE it, compose step `5a-quran` ([scripts/podcast/_book_quran.py](scripts/podcast/_book_quran.py) `inject_book`, added 2026-08-01, `R-QURAN-ARABIC-PRESENT`) puts the Arabic of every CITED Qur'anic verse onto the page — the gap the inline pass structurally could not close, since it reads the glossary and skips `>` lines, which is exactly where verse quotations live. `degrees-of-excellence` shipped 21 of its 23 cited verses as English with a bare `(5:13)` after them: the composer's input holds no Arabic, and `_book_compose._QURAN_CITE_RE` did not match a wordless `(N:M)`, so those verses were never even anchored into the prompt (that regex now accepts the parenthesised form, and citation RANGES like `(Quran 14:24-26)` are parsed too). Zero model spend and zero model judgment — the EXTENT is read off the source scan's ornate-bracketed `﴿…﴾` runs, because a book quotes a CLAUSE (`(2:282)` is 12 words of a 144-word ayah) and a whole-ayah insert would put Arabic on the page saying more than the English beside it; the LETTERS are copied from the canonical mushaf via `quran_ayat_lookup`, so OCR damage selects the window without ever reaching the page. Alignment is fuzzy-but-monotonic and segmented at large jumps, since the verse is already known from its citation and only its window is in question. A verse the scan does not print is reported UNCOVERED, never filled from a whole ayah. An UNLABELLED quotation needs TWO independent signals — a translation match in the mirror AND the same verse resolving out of the scan — before a character is written, which is what keeps the book's hadiths and its fiqh discussion off the page as scripture. Idempotent (a verse whose block already carries Arabic is skipped), it inserts above the whole blockquote so a citation on a continuation line is not orphaned, and it never rewrites an authored word. Measured as `quran_coverage` in `_system/book-arabic-audit.json` and gated by `book-challenger` **BK-N8**; existing books are backfilled with `python3 scripts/podcast/_book_quran.py --slug <slug>` (`--dry-run` first) rather than re-composed. WHICH terms, HOW OFTEN and IN WHAT FORM is governed by the **annotation policy** ([scripts/podcast/_annotation_policy.py](scripts/podcast/_annotation_policy.py), LOCKED 2026-07-22): an annotation is used ONCE and only where it helps the reader. Each glossary entry carries an `annotation_class` — `teach` (the book's own vocabulary, introduced once IN THE BOOK as `(bab, باب)`, name + script, so a reader without Arabic can still say and search the term), `familiar` (recognized English form — Quran, Mount Sinai, famous prophets — plain English, no apparatus), `name` (script once beside the romanisation), `silent` (nothing); a term is never annotated when its script is already in an adjacent quotation block, and an unclassified book keeps the legacy first-mention-per-chapter behaviour. The CLASSIFICATION is a model judgment made once per book inside compose and written into `glossary.yml` where a human can override any line durably; the model can never touch `arabic_script`. Annotations are DERIVED state — each run folds machine annotations back to their pre-annotation shape and re-derives under the current policy, so a reclassification can REMOVE apparatus. The pass runs after every LLM pass so nothing can romanize the script away again, costs nothing, and cannot fabricate: every glyph comes from the curated `arabic_script` field in `_system/glossary.yml`, with honorific formulas and name particles excluded — and that field itself is now filled deterministically first wherever possible ([scripts/podcast/fill_glossary_arabic.py](scripts/podcast/fill_glossary_arabic.py) `corpus_fill`: a unique consonant-class match against the Quranic morphology corpus, accepted only when the word's skeleton also occurs in the book's own OCR, printed unvowelled; only what the corpus cannot resolve unambiguously goes to the model). Between the policy and inline-Arabic passes runs a ONCE-per-book `0book-etymology` sub-step ([scripts/podcast/_etymology.py](scripts/podcast/_etymology.py) `build_etymology_atoms`, wired into compose 2026-07-28 after sitting caller-less since build): it mines the glossary for the book's key technical terms and generates root-level breakdowns GROUNDED in the Quranic Arabic Corpus morphology layer ([scripts/podcast/quranic_morphology.py](scripts/podcast/quranic_morphology.py) — ~1,600 human-annotated roots + ~3,000 lemmas at `content/knowledge-base/quranic-corpus/`, GPL, Kais Dukes) and the classical-lexicon join ([scripts/podcast/lexicon_ingest.py](scripts/podcast/lexicon_ingest.py) → `content/knowledge-base/lexicon.jsonl`: Lane's gloss + Maqayis/Mufradat core-sense per root, coverage-reported with no silent gaps). A term resolvable to exactly one corpus root has its root, real derived family (with verse locations) and lexicon gloss injected into the generation prompt as authoritative; the deterministic veto (corpus reference merged over the legacy `term_index`, union per key so ambiguity only ever under-fires) rejects any contradicted root; an adversarial verify pass must still confirm; and surviving atoms carry corpus script in `body.arabic` (never model recall) into `etymology.jsonl` + `knowledge.db`, id-keyed by root and reused across books. Idempotent per book via `_system/etymology-report.json`; glossary-gated, so non-Islamic routes skip at zero cost. The result is plain-transliterated ([scripts/podcast/_translit.py](scripts/podcast/_translit.py) ↔ [plan-dashboard/src/lib/translit.ts](plan-dashboard/src/lib/translit.ts)) — an ayn/hamza apostrophe is dropped outright (Quran, not Qur'an; duat, not du'at), kept ONLY where it forms an English contraction or possessive; and the English is normalized to AMERICAN spelling ([scripts/podcast/_american_spelling.py](scripts/podcast/_american_spelling.py) `to_american`) so a book cannot ship "honour" in one chapter and "honor" in the next — two separable tables (`ORTHOGRAPHY` is mechanical; `USAGE` covers toward/among and can be switched off), whole-word, fence-skipping, and scoped to prose the pipeline AUTHORS. Source records (`_system/source/`, the shared source library, third-party `research/`) are excluded by construction — respelling evidence would break the verbatim guarantee. Backfill existing books with [scripts/podcast/normalize_spelling.py](scripts/podcast/normalize_spelling.py) (dry-run by default); teaching diagrams and NotebookLM-exported slide decks ([scripts/podcast/_slide_import.py](scripts/podcast/_slide_import.py): per-chapter deck PDFs dropped at `slide-decks/chNN-<slug>.pdf` per the finalize-halt generation card → LLM-authored slide→anchor manifests, sig-cached; missing drops HALT before publish, `.SKIP` exempts) are emitted as CANDIDATES to `book/visuals/index.json` (not injected) for human curation in the Astro Book Composer, which writes `book/visual-layout.json`. `book/book.pdf` renders (Playwright) from the diagram-free `book.md`, honoring the curated layout, alongside the in-site reader view (`/studio/<slug>/book`). Knob defaults preserve each deliverable: `deliverable_mode: translation_edition → {none, faithful}` — the faithful translation edition, whose contract lives in [scripts/podcast/_translation_edition.py](scripts/podcast/_translation_edition.py) (`translation_policy.augmentation` forbids outside-source augmentation; Arabic terms and original-language text preserved from OCR/refined source; salutation prose compacted to `(عليهم السلام)`, `(ع)`, `(رض)`; monochrome visuals; `book/source-crosswalk.json` persists each chapter's source line/page ranges, headings/excerpt, Arabic page range, and title/source drift) — `content_profile: islamic_scholarly → {source_only, faithful}` (the ARTICULATION route: the faithful base plus the `0book-fluency` de-calque pass governed by the **Book Articulation Standard**, [docs/standards/book-articulation.md](docs/standards/book-articulation.md), REQ-BA-010..160; reference edition `the-master-and-the-disciple`) — and anything else `→ {source_only, author_companion}`. **The Islamic default was `author_companion` until 2026-07-31** (Asif): with `narrative_frame` enforcing who narrates, the companion re-voice had little left to do that the frame does not already do — on `the-master-and-the-disciple` six of nine chapters came back 92-100% identical to the faithful base and one byte-identical — while the fluency pass is the one written for de-calque work and the only route with a written contract. The profile is resolved through the shared [scripts/podcast/_content_profile.py](scripts/podcast/_content_profile.py) `is_islamic_scholarly`, never re-read locally, so "is this an Islamic book" has exactly one answer across the pipeline; `deliverable_mode` is still checked FIRST, so the two Mukhtasar volumes keep `{none, faithful}`. An explicit knob always wins, and every existing composed book pins both knobs or declares a deliverable mode — none inherits this default silently. Gated by `book-challenger` (semantic fidelity, the **BK-P8** articulation-conformance check on every faithful-voice book, closing with the Pass-3 narrative-frame gate) + `book-render-challenger` (print) + `book-publication-reviewer` (reader comprehension).

- **Book Composer = the singular chapter-edit path.** Human chapter edits destined for the PDF go through `/studio/<slug>/compose` only. Its save route writes `book/book.md` AND the durable sidecar `_system/composer-edits.json`. **A chapter carrying a Composer edit is NOT REGENERATED (2026-07-21):** the base compose, `0book-fluency`, `0book-augment` and `0book-voice` all consult [scripts/podcast/_book_edits.py](scripts/podcast/_book_edits.py) `edited_chapter_keys` and pass that chapter through untouched, so no model is asked to rewrite prose the replay would only discard — a rebuild that re-translated nine chapters to keep one is what this cost. (`0book-fluency` is the automatic **Book Articulation Standard** pass — REQ-BA-*, `docs/standards/book-articulation.md` — over the faithful translation-edition base; it and the Book Composer's on-demand Rearticulate action share one prompt builder, `_book_voice_prompts._articulation_prompt`, so they cannot drift apart.) `--force` re-composes regardless and warns first. `apply_composer_edits` still replays the sidecar, at compose step **5a-replay — BEFORE** the transliteration fold, the inline-Arabic pass, the spelling pass and the honorific pass, so every deterministic house-style pass sees the author's chapters as part of the book. (It ran after them until 2026-07-21, which meant the Arabic pass annotated an authored chapter and the replay then wrote the raw saved body back over the annotations; gate B3 counts Arabic runs book-wide, so nothing noticed.) Conflict detection reads ONE number produced by ONE computation: the pipeline stamps each chapter's composed fingerprint into `_system/composer-base.json` and the Composer quotes that value back as `base_fingerprint` rather than hashing anything itself — the TS `fingerprintBody` is deleted, leaving `anchor_key`/`anchorKey` as the only mirror pair. Idempotent, heading-anchored, conflict- and orphan-reporting into `_system/composer-edits-replay.json`. Directly after the replay, `_book_pass_reports.reconcile_reports_after_replay` re-stamps any pass-report chapter whose adapted prose the replay overwrote as `adapted-then-overwritten` (schemas `podcast.book-fluency/v5` / `podcast.book-voice/v5`, additive) and the compose warns loudly that paid prose was discarded (RCA-001 AI-2); a reconcile failure is recorded as its own `report-reconcile` skip, never as the replay's. The `chapters/*.txt` studio routes (`denoise`, `replace`, `save-stage`) belong to the NotebookLM lane and do NOT feed the PDF.

- **Source medium — what the book was made FROM** (`source_medium` in `_system/series-config.yaml`, resolver [scripts/podcast/_pipeline_flags.py](scripts/podcast/_pipeline_flags.py) `source_medium` / `has_printed_source`; `printed_text` | `audio_lecture`, default `printed_text`). A SOURCE property like `narrative_frame`, deliberately independent of `deliverable_mode` and `book_voice`. Added 2026-08-03 after `al-anwaar-al-lateefah` — 65 mp3 lectures recorded in URDU, transcribed and translated by Gemini, plus five augmentation series — pinned no deliverable mode, fell to the `islamic_scholarly` default `{source_only, faithful}` (the TRANSLATION-EDITION route), and was then judged by rules written for a book rendered from a printed page. Its whole spine carries FORTY Arabic runs across 65 transcripts, and REQ-BA-127 reported 189 romanized terms as a debt. They are not a debt: the lecturer said "mawaddah" aloud in an Urdu sentence, and manufacturing an Arabic page behind it is measurably worse than leaving it — a corpus fill on those terms got six of the first fourteen WRONG. Under `audio_lecture`, `_gloss_terms.bare_term_findings` returns nothing, gate B7 stops counting, and `5a-substitute` is OFF — read honestly, "the terms its glossary can prove" is none of them: all 36 of `al-anwaar`'s otherwise-eligible scripts had zero corroboration in any scan, every one from model recall, which is how it printed `آدَم` (Adam the prophet) for `عَدَم` (non-existence) past a reviewer who read the term right and never saw the pairing. The ANNOTATION still shows the script beside the romanization, offering it as a gloss rather than as the text. **Declared on the WORK and inherited by its volumes** (`work.yml`, overridable per volume): a six-volume work is one body of material, and until 2026-08-03 only volume 1 declared it while 2-6 silently resolved to `printed_text`. Nothing else changes: the book still articulates and still vowels the Arabic it does have.
- **Narrative frame — a THIRD knob, and not a product choice** (`narrative_frame` in `_system/series-config.yaml`; vocabulary + resolver in [scripts/podcast/_rules.py](scripts/podcast/_rules.py) `NARRATIVE_FRAMES` / `narrative_frame_for`, read via [scripts/podcast/_pipeline_flags.py](scripts/podcast/_pipeline_flags.py) `narrative_frame`). WHO NARRATES is a property of the SOURCE, so unlike `book_augmentation` and `book_voice` it is deliberately independent of `deliverable_mode` — a text that opens as an anonymous transmitted report stays third-person whether it ships as a translation edition or a companion book. Enforced on EVERY prose-rewriting route (`0book-compose` translation, `0book-voice` re-voice, `0book-fluency` articulation — REQ-BA-*, no longer a narrow de-calque) by the shared deterministic guards in [scripts/podcast/_narrative.py](scripts/podcast/_narrative.py): grammatical person (`R-NARRATIVE-FRAME`), speech-tag integrity (`R-SPEECH-TAG-INTEGRITY`), Arabic-script retention (`R-ARABIC-SCRIPT-RETAINED` — transliteration goes BESIDE the script, never in place of it), vowelling integrity (`R-VOWELLING-MARKS-ONLY` — **reversed 2026-07-29**: Arabic is now ALWAYS vowelled, because the reader does not read Arabic and a bare run is unreadable to him. Marks go on in TWO places: [scripts/podcast/vowel_source.py](scripts/podcast/vowel_source.py) marks the Arabic SOURCE stream once, right after 0a ingest or after the WC8 denoise (added 2026-07-30) — that is what puts marks on `glossary.yml`'s `arabic_script` at its root, and what stops every compose re-deriving marks on prose it has just regenerated — writing a `.vowelled.md` SIBLING and leaving the OCR itself untouched as the provenance record, keyed to a sha256 so a re-ingest can never leave a stale vowelling silently preferred (`_vowelled_source.resolve_arabic_source` is the one place that chooses); and [scripts/podcast/vowel_book.py](scripts/podcast/vowel_book.py) remains the net at compose time for glossary terms woven in later and anything the model dropped in transcription. What the rule still forbids is a vowelling whose consonantal SKELETON differs from its source, gated by [scripts/podcast/_vowelling.py](scripts/podcast/_vowelling.py) `rejection_reason` and mirrored in `plan-dashboard/scripts/lib/vowelling.mjs` against shared fixtures — the skeleton includes the Arabic-Indic DIGITS, and `reflow_to_source_whitespace` restores the source's line structure before the gate looks, because `skeleton()` normalises whitespace and `produce_bilingual` addresses the Arabic source BY LINE NUMBER. A Qur'anic run is the one licensed exception, set from the canonical mushaf and so legitimately Uthmani. The prose routes neither add nor strip marks; they reproduce each run as given), and enumeration survival (`R-ENUMERATION-PRESERVED` — argument lists only: a transcription's per-paragraph SECTION numbering is apparatus the edition drops by policy and is exempt. Detection is by run shape: a consecutive ascending numeric run STARTING ABOVE 1 — "(3) (4) (5)", numbering continued from earlier text, which no argument list ever does — is apparatus at any length; a run starting at 1 is apparatus only at 6+ items; lettered markers always stay policed. Refined 2026-07-22 after the gate blocked the RCA-001 recovery compose by reading a chapter slice's section numbers as a lost argument list — and its retry then "preserved" the numbers into the translation). **Lecture voice** (`R-NO-LECTURE-VOICE`, REQ-BA-125, added 2026-08-03) — under a THIRD-PERSON frame the narration never turns to the reader ("you"/"your") and never directs an audience ("Hold that frame", "Do not pass over that phrase lightly", "consider the grammar"); every such move is RECAST into exposition, never deleted, and second person inside quoted speech, verses, hadith, prayers and block quotations is untouched. Silent under a first-person frame, where addressing the reader is the form (*Ayyuhal Walad* is a letter to a disciple). Guarded DIFFERENTIALLY by `lecture_voice_findings` — a pass may not ADD lecture voice — because a lecture-derived source is saturated with it and an absolute check would revert every window before the pass could improve one; removal is driven by the prompt, and `lecture_voice_counts` is recorded per chapter as `lecture_voice_before`/`lecture_voice_after` in the fluency report so the conversion is measurable. Added after `al-anwaar-al-lateefah`, transcribed from spoken lectures, was converted to a transmitted report: every "I" changed, every lecturer's move stayed, and the chapter passed every guard while reading nothing like the edition beside it. **Navigation apparatus** (`R-NO-NAVIGATION-APPARATUS`, REQ-BA-126, 2026-08-03) — a lecture walks through a text and says where it is ("we now come to the fourth chapter of the first gate of the first canopy", "five canopies, each of five gates"); a book has a heading. The edition prints numbered chapters and has no canopies, gates, babs or fasls a reader can turn to, so the scheme names nothing they can navigate by — and `al-anwaar-al-lateefah` explained what a suradiq IS twice, four chapters apart, because the lecture did. Deliberately a RECAST rather than a strip: several of these sentences carry teaching beside the locator, so deleting the sentence deletes the thought. Same differential shape as the lecture-voice guard, and a heading or Arabic line the source prints is quoted text and stays untouched. The same module supplies the prompt directives, so the instruction and the gate state one rule. Undeclared frames fall back per content profile (`PROFILE_DEFAULT_NARRATIVE_FRAME`), conservatively: inventing a narrator is unrecoverable, failing to invent one is not. Locked 2026-07-20 after the augmented route's hard-coded "author-first-person" spec produced four narrators in one volume and re-pointed a speech to the wrong speaker. The revoice — formerly the retired per-chapter `0literary` step — lives here and NEVER feeds NotebookLM.

Compose ends with three more deterministic, non-blocking passes over the final `book.md`, each writing its own `_system/book-*.json` report: an **Arabic provenance audit** ([scripts/podcast/_book_arabic_audit.py](scripts/podcast/_book_arabic_audit.py) — folds every Arabic run to its consonantal skeleton and traces it to the source OCR or the knowledge base, flagging anything neither can account for as `unverified`; also stamps a per-stage quotation count through compose/augment/voice so a loss is attributed to the stage that caused it, not just totalled), a **visual policy check** ([scripts/podcast/_book_visual_policy.py](scripts/podcast/_book_visual_policy.py) — under the new `book_visuals: manual_only | pipeline` knob, a companion edition defaults to human-curated figures only; `0book-illustrate`/`0book-slide-import` are skipped outright and the composed markdown is scanned for every route a picture could still reach, from a stray `![]()` to an inline SVG), and a **reader-comprehension evidence pass** ([scripts/podcast/_book_comprehension.py](scripts/podcast/_book_comprehension.py) — reads the RENDERED `book.pdf`, not `book.md`, and measures prerequisite gaps against the book's own `glossary.yml`, naming drift, term-dense pages, and long sentences; wired as the final step of every PDF route, including the fiction and supplication lanes). The evidence pass feeds `book-publication-reviewer`, which judges what the evidence alone cannot and writes fixes as durable **bridges** ([scripts/podcast/_book_bridges.py](scripts/podcast/_book_bridges.py) — one sentence of orientation, anchored by quote not offset, stored in `_system/comprehension-bridges.json` and re-injected idempotently on every compose; NEVER a chapter reorder, since a faithful edition's order is deliberate).

Augmentation additionally applies a **narrator-attribution policy** ([scripts/podcast/_narrator_policy.py](scripts/podcast/_narrator_policy.py)): a knowledge-base atom whose `speaker`/`narrator` field attributes it to Abu Bakr, Umar, Uthman, or Aisha is excluded at load time, in every book-lane KB loader, before it can reach the model as a candidate — a mere MENTION of the same name in doctrinal prose is untouched, only an atom that IS a quotation from one of them.

Phases live in [scripts/podcast/_progress.py](scripts/podcast/_progress.py) `PHASES`; the book driver is [scripts/podcast/phases/book_driver.py](scripts/podcast/phases/book_driver.py).

### Determinism contract for both paths (2026-06-16)

`claude -p` exposes **no** temperature/top_p/seed flag, so LLM-authored prose (chapters, framings, `book.md`) is **reproducible-by-checkpoint, not generation-deterministic**: a *fresh* author is stochastic; a *re-run* is stable only because phases skip-if-exists (the framing-signature cache in [per_chapter.py](scripts/podcast/phases/per_chapter.py), per-SC done-markers, ENRICHED rows). Deleting an artifact or a `--force` re-extract that changes the chapter signature re-enters the stochastic path — now logged loudly at the framing cache-miss so this is observable. What IS deterministic and enforced:

- **Model provenance** — every `claude -p` call appends to `_system/model-provenance.jsonl`; a non-default model (the Sonnet timeout-fallback) is flagged `divergence:true` so a mixed-model book is visible, not silent ([_authoring/_core.py](scripts/podcast/_authoring/_core.py) `record_model_provenance`).
- **Deliverable gates** — the podcast deliverable is gated deterministically by G1–G13 at finalize ([validate_ship_ready.py](scripts/podcast/validate_ship_ready.py)); the reading-edition deliverable is gated post-render by B1–B6 ([validate_book_ready.py](scripts/podcast/validate_book_ready.py)) — B1 book.md exists and is non-trivial, B2 PDF page count is sane, B3 Islamic scholarly chapters retain Arabic script, B4 translation editions contain no model process chatter or generated opening headings, B5 translation-edition chapters have real body text, and B6 translation editions persist and pass `book/source-crosswalk.json` title/source alignment. The gate records an honest `failed` status (not silent `completed`) when broken, while staying non-blocking for the podcast; the standalone translation-edition driver treats `BOOK-BROKEN` as a hard failure because its only deliverable is the PDF.
- **Arabic script** — canonical-anchored from `content/knowledge-base/mirror.db` rather than model memory (see the PDF-compose anchoring, 2026-06-16), so scripture renders identically every run.
- **Transcription normalization** — pure, idempotent, data-driven ([data/transcription-normalization.yml](scripts/podcast/data/transcription-normalization.yml)); a malformed map now warns loudly instead of self-disabling silently.

## Audio engines — manual NotebookLM (default) vs autonomous ElevenLabs (2026-06-12)

The podcast path's AUDIO step is engine-pluggable. A book declares `audio_engine: notebooklm | elevenlabs` in `_system/series-config.yaml`; a missing field means `notebooklm`, and every pre-existing book behaves byte-identically (golden-fixture regression in [scripts/podcast/tests/test_audio_engines.py](scripts/podcast/tests/test_audio_engines.py)). The registry — capability flags (`supports_arabic_script`, `supports_audio_tags`, `max_chunk_chars`, `credit_rate`, `render_mode`), pinned model id, default voice casting — is [scripts/podcast/_audio_engines.py](scripts/podcast/_audio_engines.py); adding an engine is one entry there (extensibility-first), and validators / cost estimator / orchestrator read capabilities from it, never from hardcoded conditionals. Voice casting resolves through the **voice library** ([scripts/podcast/voice-library.yaml](scripts/podcast/voice-library.yaml) + [scripts/podcast/_voice_library.py](scripts/podcast/_voice_library.py)) — the Asif-approved male/female pools (2026-06-12 casting rounds; clear English + correct Arabic phonetics on native script): each book gets a deterministic per-slug pair, overridable per book via series-config `voice_cast:` (library names) or `elevenlabs_voices:` (explicit IDs, highest priority). Adding a voice is one YAML entry.

- **NotebookLM (manual, default).** Finalize halt prints the upload table AND writes a durable worklist (`_system/notebooklm-worklist.md`, via [`_notebooklm_table.build_worklist_lines`](scripts/podcast/_notebooklm_table.py)) the operator works across sessions: upload table + slide-deck card + a live per-episode drop-target checklist. The human uploads chapter + framing and downloads `.m4a` anywhere under `m4a/`. The post-drop processing is then AUTOMATIC: the **`audio-ingest`** phase ([scripts/podcast/phases/audio_ingest_driver.py](scripts/podcast/phases/audio_ingest_driver.py), in `PHASES` between `finalize` and `0book-design`, driven at the top of `publish_driver._drive_publish_through_done`) fingerprint-repairs filename drift (`normalize_m4a`), Azure-transcribes (`transcribe_notebooklm`), and gates on completeness — re-halting cleanly (rc 3) until every NotebookLM episode has audio + transcript, then continuing into the book branch + publish. It is an engine-gated no-op (`skipped`) for autonomous/ElevenLabs books and resolves the NotebookLM episode set through the shared [`_audio_engines.notebooklm_episode_filter`](scripts/podcast/_audio_engines.py) (the same helper the finalize halt uses). No manual `normalize_m4a.py` / `transcribe_notebooklm.py` invocation is needed (they remain standalone tools). Tests: `tests/test_audio_ingest_driver.py`, `tests/test_notebooklm_worklist.py`.
- **ElevenLabs (autonomous).** Two phases between `per-chapter-slides` and `finalize` in `PHASES`:
  - **audio-script** — per-chapter two-host dialogue script ([scripts/podcast/_authoring/_dialogue.py](scripts/podcast/_authoring/_dialogue.py), Claude Max, the authored framing is the steering spec) converged through the pre-synthesis gate ([scripts/podcast/_validators_dialogue.py](scripts/podcast/_validators_dialogue.py) deterministic + semantic challenger pass in [scripts/podcast/_dialogue_convergence.py](scripts/podcast/_dialogue_convergence.py)). Deny lists, doctrine, honorifics, host parity, engine-aware Arabic/tag rules, and a deterministic COVERAGE check (every contract tension/concept surfaced — no-teaching-lost) gate the script; the SOFT char band is a P2 pacing advisory and NEVER cuts content. Verdicts: SHIP-READY / SHIP-WITH-CAUTION / FAILED; findings flow to `_learning/findings.jsonl` (`source=dialogue-gate`). NOTHING renders before a passing verdict.
  - **audio-render** — ONE halt per book (H1) surfaces the exact deterministic credit estimate (chars x registry rate); `--resume` approves. [scripts/podcast/render_dialogue_audio.py](scripts/podcast/render_dialogue_audio.py) then renders via `eleven_v3` text-to-dialogue ([scripts/podcast/_elevenlabs.py](scripts/podcast/_elevenlabs.py)) straight into the canonical layout (`m4a/ch<NN>-<slug>.m4a` + both transcript contracts — the transcript IS the speaker-labeled script; no STT spend). Determinism contract: pure chunker (<= 2,000 chars at turn boundaries), hash-derived per-chunk seeds, pinned model/voices/settings/dictionary-version, render ledger (`_system/render-ledger.jsonl`, input-hash -> output-hash) + chunk cache — unchanged chunks never re-render or re-spend. Exact credits metered from the subscription delta into `cost-ledger.jsonl` (`elevenlabs-eleven-v3` rows). Neural TTS is best-effort reproducible; the pipeline's determinism is input-determinism + the ledger.
- **Pronunciation (NotebookLM lane)** — the framing's `## Pronunciation` block is COMPILED, not authored (R-PRONUNCIATION-RENDER, 2026-08-01). The model chooses which terms need help; [scripts/podcast/_pronunciation_block.py](scripts/podcast/_pronunciation_block.py) resolves every value through the one shared ladder in [scripts/podcast/knowledge/term_render.py](scripts/podcast/knowledge/term_render.py) — per-book override table (`_system/pronunciation.md`) → loanword → English exonym → `confirmed` row in the cross-book ledger → gloss → plain transliteration — filtered to the terms that actually appear in THAT chapter, in reading order, trimmed from the end if the framing would exceed the Customize ceiling. A term the ladder can only spell back gets NO entry and is reported for the probe, because "say arkan as arkan" is not guidance. The block degrades to the authored text when nothing resolves, and `assert_framing_pronunciation_render` refuses a translation left in the value slot. This replaced free-text authoring after five of six `degrees-of-excellence` episodes shipped with an English gloss where the block promised a phonetic, and the hosts pronounced the gloss. Settle an unknown term by ear with [scripts/podcast/run_pronunciation_probe.py](scripts/podcast/run_pronunciation_probe.py); the verdict lands in `content/knowledge-base/pronunciations.jsonl` and every later book inherits it.
- **Pronunciation (ElevenLabs lane)** — a separate mechanism for a separate engine, deliberately not merged: [scripts/podcast/pronunciation_compiler.py](scripts/podcast/pronunciation_compiler.py) deterministically compiles `_system/glossary.yml` into an ElevenLabs alias-rule PLS dictionary (alias rules work on all models; phoneme rules deliberately unused), uploads once per book, pins `{dictionary_id, version_id}` in `_system/pronunciation-dictionary.json`, and recompiles to a new pinned version on glossary change (history ledger). Arabic-script recitation is a render-layer scaffold behind `elevenlabs_arabic_recitation` (default OFF; flips only after the H2 audible-sample review).
- **Site** — the Astro site reads the same canonical layout for both engines; the studio Publish step surfaces the book's engine + exact rendered-credit spend. The **new-content intake form** ([plan-dashboard/src/components/intake/VoicePicker.tsx](plan-dashboard/src/components/intake/VoicePicker.tsx)) lets the operator pick the engine and one male + one female from the approved pools (monogram avatars, accent labels, per-voice sample clips served from `public/voice-samples/`, sourced via [plan-dashboard/src/lib/voice-library.ts](plan-dashboard/src/lib/voice-library.ts) → `voice-library.yaml`); the choice is stamped into series-config at launch.

**NotebookLM is the default for Islamic content; ElevenLabs is quarantined (LOCKED 2026-06-13, supersedes the brief 2026-06-13 ElevenLabs-default).** `_rules.audio_engine_default_for_profile('islamic_scholarly')` returns `notebooklm` — confirmed against the-master-and-the-disciple + Asas al-Taweel Vol 1 (ElevenLabs scripted dialogue was tried for Vol 1 and rejected: robotic, no emotional spontaneity). **ElevenLabs is retained but DORMANT** — a quarantine marker sits on the `ENGINE_ELEVENLABS` registry entry in [scripts/podcast/_audio_engines.py](scripts/podcast/_audio_engines.py); nothing load-bearing was removed, so it remains the only autonomous engine and can be reactivated per book via `audio_engine: elevenlabs`. The intake default is stamped from the registry in `_rules.py` by [scripts/podcast/intake_launch.py](scripts/podcast/intake_launch.py) and never applied retroactively. Mixed-engine books are still supported **per-episode** via `episode_engine_overrides: {EP##-slug: notebooklm}`: `engine_for_episode()` routes each episode, the ElevenLabs script + render phases skip overridden episodes, the `audio-ingest` phase processes only the NotebookLM subset, and the finalize halt prints the "already rendered" note (API episodes) alongside the NotebookLM upload table filtered to the overridden episodes. No overrides → unfiltered table, byte-identical to before (golden-test latch).

**Deterministic Arabic recitation (2026-06-13).** ElevenLabs pronounces Arabic, so an Islamic book RECITES verses + key terms in native script — but the Arabic is NEVER typed by the model (scripture recited wrong is a doctrinal error). It is injected at the render-compile layer ([scripts/podcast/pronunciation_compiler.py](scripts/podcast/pronunciation_compiler.py) `compile_turns_for_render`, ElevenLabs-only, gated by `elevenlabs_arabic_recitation`, default-ON for Islamic books at intake) from two VERIFIED, deterministic sources: (1) Quran verses — [scripts/podcast/_quran_recitation.py](scripts/podcast/_quran_recitation.py) resolves a citation ("the chapter of Abraham, verse seven" or "(chapter 14, verse 7)") to `(surah, ayat)` via a canonical surah table + exact number parse, then reads the verbatim Arabic from the wisdom corpus **KQur** (`content/knowledge-base/mirror.db` `fts_quran`, via `quran_ayat_lookup`) and splices it after the citation; an unresolved or non-existent verse is logged and left in English, never guessed. (2) Key terms — glossary phonetic→`arabic_script`, skipping loanwords and personal names (referential names are pronounced via the alias dictionary, not recited). The dialogue author writes ASCII only and never types Arabic; the shared chapters + script artifact stay engine-neutral and phonetic, so NotebookLM is byte-identical. Noise stripping is unchanged and engine-independent. Hadith recitation is deferred (the `Ahadees` table needs its own deterministic key).

**NotebookLM style fidelity (2026-06-13).** The autonomous path is steered toward the NotebookLM sound at three layers: (1) the dialogue-authoring prompt encodes the seven NotebookLM conversational moves (cold-open hook, interruption echoes, two pushback-and-concede arcs, short reactive beats, mid-thought handoffs, recurring refrain, direct-to-listener close), allows native Arabic script + gloss when the engine supports it, and forbids tonal tags on the scholar voice (reaction tags on the seeker only); (2) the pre-spend challenger ([scripts/podcast/_dialogue_convergence.py](scripts/podcast/_dialogue_convergence.py)) judges each move's genuine presence, and the deterministic gate carries a registry-driven tag budget + the tonal-tags-on-HOST_A check + light style nudges; (3) a post-render **style gate** fingerprints the audio against a tracked per-genre gold standard ([content/_shared/audio-style/islamic_scholarly.json](content/_shared/audio-style/islamic_scholarly.json), built from BOTH NotebookLM books by [scripts/podcast/build_audio_gold_standard.py](scripts/podcast/build_audio_gold_standard.py) via [scripts/podcast/_audio_fingerprint.py](scripts/podcast/_audio_fingerprint.py)) and, when below threshold, renders ONE bounded retake (inside the H1-approved spend) and keeps the better take — a quality flag, never a hard block.

## Single-machine model

The pipeline is **machine-agnostic**. Most work is done by Anthropic + Azure remotely (LLM calls, OCR, translation, speech), so the host machine carries no special-snowflake configuration. The repo runs the same way on any Mac with `python3`, `git`, and the Azure stack credentials (per [docs/setup/azure-stack.md](docs/setup/azure-stack.md)).

- **Per-content branches, grouped by content bucket (locked 2026-06-07, supersedes the 2026-06-04 bare-slug model).** Every new piece of content is processed on its own branch off `develop`, named `<Bucket>/<full-slug>` (e.g. `Fiction/journey-to-the-west-vol-1`, `Islamic/ayyuhal-walad`) via [scripts/podcast/_branching.py](scripts/podcast/_branching.py) — `branch_name(category, slug, *, profile=None, bucket=None)` returns `<Bucket>/<slug>`, resolving the bucket from `content_profile` (via the shared `_paths.resolve_bucket`, so branch bucket == folder bucket) and falling back to a coarse `category` map (defaulting to Islamic). ## Setup stage — pre-pipeline system check (added 2026-06-07)

Before any pipeline work runs, the orchestrator executes a **Setup stage** that resolves machine-readiness problems up front instead of crashing deep inside a phase. Two parts:

1. **Interpreter self-heal** ([scripts/podcast/orchestrate_book.py](scripts/podcast/orchestrate_book.py) `_ensure_capable_interpreter`) — if the active interpreter can't `import yaml`, the orchestrator transparently re-execs under the repo virtualenv `.venv/bin/python` (which carries PyYAML/anthropic/requests). A sentinel env var (`_PODCAST_REEXECED`) prevents an exec loop; a missing/incomplete venv surfaces an actionable `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`. This eliminates the failure mode where system `python3` (lacking deps) crashed every phase at `import yaml` and the watchdog mis-reported it as "working tree dirty".

2. **Doctor / system check** ([scripts/podcast/preflight_doctor.py](scripts/podcast/preflight_doctor.py) `run_doctor`) — runs at the top of `main()` for BOTH initial and resume, **before the watchdog is spawned**, so a failure fails fast with the exact fix command instead of the watchdog retry-looping a doomed run 20×. Four checks: **deps** (yaml/anthropic/requests importable), **claude-auth** (keychain OAuth-token expiry pre-check + a live `claude -p` ping mirroring `_run_claude_p`'s API-key-stripped Max path; a 401/expired token halts with `claude login`), **anthropic-net** (api.anthropic.com:443 reachable), **azure** (OCR/Translate probe — skipped automatically on resumes where phase 0a already completed). Flags: `--doctor` runs only the check and exits (0=ready, 1=blocked); `--skip-doctor` bypasses it (use only when the failing subsystem is unused by the phases being run). The watchdog ([scripts/podcast/watch_orchestrator.sh](scripts/podcast/watch_orchestrator.sh)) also prefers `.venv/bin/python` for the same dependency reason.

## Conventions

- **No emojis in code or commits** unless explicitly invited.
- **Status emojis (🟢 🟡 🔴 ⚠) in responses** per the response template (canonical at `~/.claude/response-template.md`).
